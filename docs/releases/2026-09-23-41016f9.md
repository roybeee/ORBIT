Content: three fixes that had accumulated since `b0c9c58`.

- A planning run that fails after it started now fills a missing plan for that date with the deterministic BRAINY planner instead of leaving the day empty, and a spent provider quota skips the smaller-catalog retry ladder (#54).
- The Slack directive readback no longer reads a server-assigned `updated` stamp as an edit, so a directive filed on any day but the server's today stops reporting `target_changed` the moment it is written (#55).
- Notification groups are keyed by the head notification's id instead of its kind and title, so repeated titles no longer share a React key (#56).

Verified in production after the deployment: the notification inbox renders 18 rows for the 18 groups its 32 records form, with no duplicated row (before this release the same 32 records rendered 26 rows, with single notifications drawn twice at different positions). Dismissing a row with the X button removed it and it stayed removed across the 12-second refresh, which is the reported fault this release closes.
