# Orbit 1차 운영 개선

- 서버가 접수된 대화·연결 자료 분석을 지속하며 선택 캘린더와 Gmail을 약 15분 간격으로 확인합니다. Plaud는 분석에서 요청한 실제 조회만 성공으로 기록합니다.
- 저녁 기본 21시(워크스페이스 시간대)에 다음 날 제안을 준비합니다. 새벽 장애 복구 시 오늘 누락된 제안만 보충하며, 기존 계획은 덮어쓰지 않습니다.
- `하루 운영`에서 활성 상태·마지막 서버 확인·수집 범위·오류·제안 결과를 확인하거나 일시 정지할 수 있습니다. 승인 대기 작업은 자동 승인하지 않습니다.
- 1분 회고는 확인한 결과만 저장합니다. 기기 초안과 다른 기기의 최신 회고가 다르면 사용자가 선택합니다.
- 실행실은 완료 기준·검증 근거·검토 시각을 결과 본문 해시에 연결합니다. 결과 검토와 할 일 완료는 별도 명시적 동작입니다.
- 대화, 새 기록 작성, 회고와 미확인 저장 요청을 로그인 계정별 기기 임시 저장소에 보관합니다. 서버 기록의 오프라인 복사본은 아닙니다. 브라우저 저장소 삭제·시크릿 모드에서는 보존되지 않을 수 있습니다.
- 받은 공유 파일은 현재 계정으로 보관하기를 선택한 뒤 업로드하며, 자동 시간 만료로 삭제하지 않습니다. 최대 대기 10건이며 직접 정리할 수 있습니다.
- Google 캘린더를 최대 10개 선택합니다. 하나라도 조회에 실패하면 기존 캐시를 유지하고 실패를 표시합니다.
- 승인된 집중 시간의 `Google에도 등록`은 기본 캘린더에 알림·초대 없이 명시적으로 등록합니다. 같은 블록은 같은 원격 ID를 사용하며 응답 유실 시 재확인합니다. 등록 중 내부 변경은 잠시 차단합니다. Orbit 승인 취소는 Google 이벤트를 삭제하지 않습니다.

## 예약 실행기

`scripts/runtime-tick.mjs`를 매분 실행합니다. 한 실행에서 최대 12단계를 진행하고 대기 포함 약 50초에 다음 요청 시작을 멈춥니다. 단일 외부 요청 제한은 150초이며 Orbit 내부 임대는 180초입니다. 서버는 한 요청당 하나의 자료 수집 또는 실행 단계만 수행합니다. Render cron의 단일 실행 보장과 DB 임대로 중복 처리를 막습니다.

실행기 생성 및 작동 검증 후 Sites 환경변수 `ORBIT_SCHEDULER_ENABLED=1`을 설정하고 다시 배포합니다. 이 값이 없으면 화면은 예약 실행기 연결 대기로 표시합니다.

Sites 비밀 환경변수: `ORBIT_RUNTIME_KEY`, `ORBIT_RUNTIME_OWNER`.
Render 비밀 환경변수: `ORBIT_RUNTIME_TICK_TOKEN`, `ORBIT_SITES_BEARER`. URL은 `ORBIT_RUNTIME_TICK_URL`입니다. 키와 고정 소유자는 모델·브라우저 입력으로 설정되지 않습니다. transport bearer는 Sites 게이트 전용이며 앱 사용자 신원을 부여하지 않습니다.

배포된 소스는 Sites 저장소의 커밋으로 고정하며, GitHub 미러 쓰기 권한이 복구되면 같은 파일 트리를 반영합니다. 토큰이나 환경변수 값은 소스에 저장하지 않습니다.
