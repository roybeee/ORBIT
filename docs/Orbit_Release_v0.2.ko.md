## 사용 시작 순서

1. 앱을 열고 첫 프로젝트의 이름·최종 결과·목표일을 입력합니다.
2. 할 일을 추가하고 완료 기준을 적습니다. 지금 중요한 일은 ‘핵심 결과물로 지정’을 선택합니다.
3. 회의록이나 참고 자료를 위키·지식창고에 저장하고 프로젝트에 연결합니다.
4. 저녁 회고에서 결과와 미완료 이유, 다음 날의 에너지를 기록합니다.
5. 생성한 제안의 시간과 이유를 확인하고 승인합니다. 승인한 날짜의 일정에 집중 시간이 생깁니다.
6. 진행이 어려운 일은 보류 이유와 다음 검토일을 정합니다.

설정은 왼쪽 사용자 이름 옆 버튼에서 엽니다. 모바일에서는 ‘더 보기’로 탐색 메뉴를 열면 찾을 수 있습니다.

## 저장과 충돌 처리

성공 응답을 받기 전에는 저장 완료라고 표시하지 않습니다. 저장이 지연되거나 실패하면 입력 폼을 유지하고 같은 요청 번호로 재시도합니다. 이미 저장된 요청을 다시 보내도 중복 반영하지 않습니다.

다른 기기가 먼저 수정한 경우 오래된 내용으로 덮어쓰지 않습니다. 최신 내용을 다시 불러온 뒤 작성 중인 폼을 검토해 적용할 수 있습니다. 자동 새로 불러오기는 열려 있는 화면에서 1분 간격과 창 복귀 시 수행하며, 미확인 저장 요청이 있거나 입력 폼·회고를 작성 중이면 중단합니다.

일정 승인·집중 시간·핵심 결과물 반영은 하나의 서버 변경으로 저장됩니다. 승인하지 않은 초안은 일정을 만들지 않습니다. 업무 완료와 일정 시간의 경과는 별개입니다.

## 현재 범위

- 제안은 규칙 기반입니다. 회고 문장 자동 분석과 LLM 호출은 아직 없습니다.
- 일정은 Orbit 내부에 저장됩니다. Google Calendar·Notion 자동 동기화는 아직 연결하지 않았습니다.
- 저녁 자동 알림·정해진 시간의 자동 제안 생성은 아직 활성화하지 않았습니다. 현재는 앱에서 실행합니다.
- 실제 작업 시간 측정, 파일 첨부, 전문 검색, 위키 버전 복원은 후속 단계입니다.
- JSON 내보내기는 지원하지만 가져오기·삭제 복원 기능은 아직 없습니다. 삭제 시 확인 창을 표시합니다.
- PWA 설치 파일과 오프라인 안내를 구성했습니다. 실제 휴대폰의 설치·재로그인 검증은 수행하지 않았습니다. 오프라인에서 업무 데이터는 열람하거나 저장할 수 없습니다.
- 사용자 GitHub 저장소는 아직 접근할 수 없습니다. 코드·변경 이력·검증 파일은 앱의 전용 Git 저장소에 보존하고 GitHub 연결을 준비했습니다.

## 검증

서버 저장과 계정 분리, 동시 수정 충돌, 요청 재시도, 승인 트랜잭션, 보류일, 날짜 경계 등 10개 테스트를 실제 생성 SQL을 적용한 로컬 SQLite에서 수행했습니다. 기존 제안 엔진 8개와 빌드된 서버의 로그인·API·예시 분리 5개 테스트도 통과했습니다.

타입 검사·프로덕션 빌드·서비스 워커 구문·설치 아이콘 크기를 확인했습니다. 브라우저 화면과 실제 기기의 동작은 별도 검증 범위입니다.
