# Orbit · 목표를 챙기는 비서실장

Orbit의 판단 단위는 할 일 개수가 아니라 사용자가 확인한 목표의 성과다. 일·사업, 건강, 마음·회복, 학습, 삶의 목표를 연결하고 지금 할 수 있는 한 가지를 찾는다.

## 시작하기

1. 대화 첫 화면의 **나의 궤도 → 목표 관리**에서 목표 분야, 기한, 실제 수치를 정한다. 기존 목표는 **진척·분야 수정**으로 시작값·현재값·목표값·단위·시작일을 기록한다. 프로젝트를 목표에 연결한다.
2. **30초 체크인**으로 오늘 에너지와 부담, 필요한 도움을 남긴다. 모르는 상태를 낮은 의지나 실패로 추정하지 않는다.
3. 지금 필요한 한 가지를 시작하거나 **함께 풀기**로 Hermes에 해결을 요청한다. **막혔어요**는 이유를 기억하고 할 일을 대기로 옮긴다. 60분 뒤 재확인하며, **30분 뒤**는 해당 제안을 잠시 숨긴다.
4. **비서실장 설정**에서 말투, 조용한 시간, 운동·마음 돌봄·학습 루틴을 정한다. 루틴에 등록한 시간은 새 실행 제안의 업무 배치에서 제외한다. 실제 실천 후 완료를 기록한다.

## 판단 원칙

- 실제 진행 중인 집중 세션을 보호한다. 낮은 에너지·버거움에는 회복이 먼저다. 쉬는 중에는 새 업무를 바로 제시하지 않는다.
- 마감·목표 연결·실제 수치의 기준 속도와 준비 상태로 다음 행동을 정한다. 보류·대기·미완료 선행 작업은 바로 시작할 후보에서 제외한다.
- 목표 수치가 없거나 7일 넘게 갱신되지 않았다면 현재 위치를 확인한다. 선형 속도는 참고선이다. 숫자에 도달해도 목표 달성은 사용자가 결과를 확인한다.
- 남은 업무 시간에서 겹치는 일정, 돌봄 시간, 여유분을 제외해 과부하를 판단한다. 이미 일정에 잡힌 작업을 중복 계산하지 않는다.
- 기록 없는 날을 실패로 세지 않는다. 단호함은 근거와 다음 행동을 분명히 하는 것이며, 수면·회복을 희생시키거나 비난하는 방식이 아니다.
- 개인 목표에는 타인에게 전달하는 결과물 대신 스스로 확인할 수 있는 실천·학습 결과도 완료 조건이 된다.

## 앱을 닫아도 챙기기

**비서실장 설정 → 앱을 닫아도 챙기기 → Hermes 예약 상태 확인**에서 설정한다. 6·12·24시간 간격, 전달 방식, 조사할 최신 정보 주제를 선택하고 전달 범위를 확인한 뒤 예약한다. 예약을 켜는 작업은 사용자 화면에서 명시적으로 실행한다.

- Hermes의 `/api/jobs`가 필요하다. 기존 HTTPS gateway와 연결 암호를 사용하며 별도 모델 API로 전환하지 않는다.
- **Hermes에 보고서 보관**은 휴대폰 알림을 보내지 않는다. **내 Telegram**은 Hermes에 본인 수신 채널이 연결되어 있어야 한다. 보고서 본문은 선택한 채널에서 읽는다.
- Orbit을 사용하는 동안 목표·진척 스냅샷을 갱신한다. 자동 갱신은 이미 승인한 예약에만 적용되며, 설정한 전달 범위를 확대하지 않는다.
- 새 회의·메일·일정이 닫힌 Orbit에 들어온 순간 감지하는 상시 감시 기능은 아니다. 예약 실행은 마지막 스냅샷의 시점을 밝힌다. 48시간 넘게 지난 기록으로 현재 지연을 단정하지 않는다.
- 최신 정보 조사는 Hermes의 읽기 전용 웹 검색이 가능할 때 진행하며, 직접 출처와 확인 날짜를 포함하도록 요청한다. 조회 실패를 최신 정보 확인으로 표시하지 않는다.
- Hermes가 켜져 있어야 한다. Mac의 잠자기·종료·연결 끊김과 외부 서비스 오류는 예약 실행이나 전달을 막을 수 있다. 실행 상태와 전달 실패는 구분해 표시한다.
- 조용한 시간과 24시간 쉬기 설정은 앱 사용 중 예약 프롬프트에도 전달한다. 전달 실패 시 화면에 알리며, 예약을 직접 일시 정지할 수 있다.

닫힌 앱에서 최신 비공개 Orbit 기록을 읽고 판단한 결과를 Orbit 알림함과 Web Push로 배달하는 상시 서비스는 후속 작업이다. 현재 Sites의 로그인 경계를 우회하는 인증 수단을 예약 에이전트에 제공하지 않는다.

## 개발·검증

도메인 판단은 `lib/orbit/chief.ts`, 사용자 변경은 기존 workspace revision/operation 체계를 사용한다. 루틴·체크인은 소유자 데이터에 저장된다. 예약 실행은 별도의 소유자별 잠금과 확정/미확정 영수증을 사용해 응답 유실 시 중복 생성과 잘못된 성공 표시를 방지한다. 개인 위키·메일 원문이나 연동 암호는 예약 프롬프트와 GitHub에 복사하지 않는다.

`npm run test:chief`는 목표 진척, 낮은 에너지, 휴식, 재확인, 자정 전환, 계획 충돌, 보류 목표, 저장 충돌, 예약 재시도·격리·범위 제한을 검증한다. 실제 소유자 Hermes에서의 실행과 개인 Telegram 전달 여부는 연결 후 실제 상태로 확인해야 한다.
