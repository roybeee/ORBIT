## 2. 원칙

1. **탭 = 사용자의 질문.** 설계서 §1의 다섯 질문을 탭 경계로 쓴다. 시스템 모듈로 나누지 않는다.
2. **숨은 메뉴 0.** 모든 화면은 탭 → 화면 칩(한 줄, 보이는 상태) 두 단계 안에 있다. 드롭다운·햄버거 뒤에 기능을 두지 않는다.
3. **결정은 한 곳.** 승인·보류·확인이 필요한 것은 결재함에 출처와 함께 모인다. 빨간 숫자는 “내가 정해야 하는 것”에만 쓴다. 읽기만 하는 소식은 점(•)으로 표시한다.
4. **AI는 곁에.** Orbit은 탭이 아니라 가운데 버튼·오른쪽 도크로 어디서나 연다. 보고 있던 화면이 맥락으로 따라간다.
5. **하루의 시간이 화면을 바꾼다.** 오늘 탭의 첫 카드는 아침·낮·저녁에 따라 바뀌고, 현재 모드와 수동 전환을 항상 보여 준다(놀라게 하지 않는다).
6. **위치를 바꾸고 기능은 지킨다.** View id·딥링크(`#view`, `?note=`, `?task=`, `?conversation=`, `?order=`)·PWA 바로가기는 유지한다. 컴포넌트는 옮기되 다시 쓰지 않는다.

## 3. 구조

| 영역 | 화면(View id) | 답하는 질문 |
|---|---|---|
| **오늘** | today · calendar · review · proposal · dashboard · voice | Q1 오늘 무엇을 끝내야 하나 · Q5 내일은 |
| **결재함** | inbox(신규) · followup | Q4 내가 정할 일 |
| **◎ Orbit** (가운데 버튼, 탭 아님) | agent · aside | 어느 화면에서나 묻고 맡기기 |
| **프로젝트** | projects · tasks · goals · portfolio · signals · meetings · experiments · contacts | Q2 어디가 막혔나 · Q3 왜 시작됐나 |
| **기록** | wiki · knowledge · understanding · monthly · learning | Q3 쌓인 기록에서 답 찾기 |
| **나** (우측 상단·사이드바 하단) | automation · sound · data · backup + 설정 | 가끔 쓰는 관리 |

26개 기존 화면이 모두 한 곳에 속한다(`lib/orbit/navigation.ts`가 단일 정의, 테스트가 누락·중복을 막는다).

## 4. 화면별 UX 명세

### 4.1 셸
- **모바일(<768px):** 하단 5칸 = 오늘 · 결재함(배지) · ◎Orbit(떠 있는 원형, 라벨 “Orbit”) · 프로젝트 · 기록. 상단 = 탭 이름 · 찾기 · 나. 키보드가 열리면 하단바 숨김(기존 규칙 유지).
- **데스크톱(≥768px):** 왼쪽 사이드바 = 4탭 + Orbit 버튼 + 찾기(⌘K) · 하단 사용자 상자 → 나.
- **화면 칩:** 탭 제목 아래 한 줄. 현재 화면 `aria-current="page"`. 넘치면 가로 스크롤(스크롤 가능함을 끝 페이드로 표시). 결재함 칩에는 배지.
- **찾기(⌘K / Ctrl+K):** 기존 ‘전체 메뉴’를 대체. 27개 화면 + 바로 하기(새 할 일·새 일정·새 프로젝트·회고 시작·Orbit에게 묻기·설정). 옛 이름 별칭(전체 메뉴, 알림, 대화, 검토함 등)으로도 찾힌다. 방향키·Enter·Esc.
- **처음 한 번 안내:** “메뉴가 한 궤도로 바뀌었어요” 카드(기기별로 한 번, 닫으면 다시 안 뜸). 옛 경로 → 새 위치 3줄과 ‘찾기 열기’.

### 4.2 결재함
- 머리: “내가 정할 일 N” + 한 줄 설명(승인한 항목만 반영, 외부 발송은 따로 확인).
- 필터 칩: 전체 · 계획 · AI 제안 · 업무 지시 · 확인일.
- 카드 공통: 종류 배지 · 출처 한 줄 · 제목 · 근거 · 행동(승인 / 보류(이유+재검토일) / 자세히). 처리 후 카드는 “승인됨/보류됨” 상태로 잠시 남고 사라진다(되돌리기 경로는 원래 화면).
- 소식: 읽기만 하는 알림. 점 표시, ‘모두 읽음’.
- 배지 수 = 오늘 이후 계획의 대기 항목 + 대기 중 AI 카드(`state==='pending'`) + 승인 대기·결과 확인 대기 업무 지시 + 확인일이 된 결정·위임. 알림은 파생 기록이라 더하지 않는다(중복 방지).
- 빈 상태: “지금 정할 일이 없습니다.” + 다음 예정(내일 제안 준비 시각).

### 4.3 오늘 (시간 모드)
- 모드 판정(`lib/orbit/day-mode.ts`)은 서버와 같은 저녁 기준(`RuntimeConfig.eveningHour`, 기본 21시, `GET /api/runtime`)과 업무 시작 시각을 쓴다. 아침 = 04시부터 업무 시작 후 1시간까지, 낮 = 그 뒤부터 저녁 전, 저녁 = 저녁 시각부터 다음 날 04시 전.
- 모드 표시: 첫 카드 위 “지금 · 저녁 모드 ▾”. 눌러서 다른 모드로 볼 수 있다(그날만).
- 아침 첫 카드: 오늘의 한 가지(Goal Laser) + 어제 회고 개선점 + ‘오늘 계획 승인 N’ → 결재함.
- 낮 첫 카드: 지금 한 가지 + 집중 타이머 + 사운드 미니 + 끝냄.
- 저녁 첫 카드: PAFI 회고(기존 ReviewWizard) → 저장 시 내일 제안 생성 → 결재함 배지.
- 그 아래는 공통: 오늘 흐름(일정), 막힌 일, 진행 프로젝트. ‘하루 | 주간’ 전환으로 일정 화면.
- 데모는 시각이 고정이므로 모드 전환 칩으로 세 모드를 모두 볼 수 있다.

### 4.4 Orbit 도크
- 대화 컴포넌트는 **한 인스턴스만** 유지한다(스트림·전송 잠금이 인스턴스 단위). 도크는 같은 인스턴스를 담는 그릇이다.
- 모바일: 아래에서 올라오는 시트(높이 88%), 뒤로 가기로 닫힘. 데스크톱: 오른쪽 패널(열림 상태 기억).
- 맥락 칩: “맥락: 프로젝트 ○○” 등. 메시지 전송 시 본문 앞에 맥락 한 줄을 붙인다(서버 스키마 변경 없음).
- 빠른 기록 4개: 할 일 · 일정 · 메모·회의록 · 업무 맡기기.
- 11곳에 복제된 `navigate('agent')+orbit:compose`를 `askOrbit(text)` 하나로 모은다.

### 4.5 프로젝트
- 탭 머리: 목표 사다리 요약(꿈 → 중장기 → 단기, 접힘).
- 화면 칩이 곧 보기 전환: 프로젝트 · 할 일 · 목표 · 시간 배분 · 운영 신호 · 회의 브리핑 · 사업 실험 · 사람·거래처.
- 상세 시트 탭: 개요 · 할 일 · 회의·결정 · 기록 · 대화(프로젝트 대화 바로 열기).

### 4.6 나
설정(업무 시간·BRAINY 리듬), 계정·연결, 자동 실행(내일 제안 준비 시각), 서버 자동화, 사운드스테이션, 데이터 관리, 백업·복구, 앱 설치·화면.

### 4.7 공통 품질 기준
- 터치 영역 44px 이상, 포커스 표시, `prefers-reduced-motion` 존중, 색만으로 상태를 표현하지 않음(텍스트 병기).
- 배지 숫자 99+ 상한, 스크린리더 라벨 “결재함, 정할 일 3건”.
- 도시 스킨·코스믹 테마 위에서도 동작(새 스타일은 `app/orbit-shell.css`, 마지막에 로드).
