# 프로젝트 자동 안분과 연결 그래프

할 일 제목·완료 기준을 기존 프로젝트 이름과 명시적 키워드에 대조한다. 등록한 키워드와 긴 이름의 명확한 일치가 우선이며, 다른 프로젝트와 비슷하게 일치하거나 학습한 업무 일반어만 일치하면 자동 이동하지 않는다.

- 새 할 일: 기존 프로젝트가 분명하면 자동 선택. 대상이 없으면 제목의 사업명 또는 채용/자금 업무 분류로 새 프로젝트 후보를 표시한다. 저장 시 프로젝트와 할 일을 한 트랜잭션으로 생성한다. 사용자가 프로젝트를 직접 고른 경우 그 선택을 유지한다.
- 기존 할 일: **프로젝트 → 자동 안분** 또는 **할 일 → 프로젝트 자동 안분**에서 생성할 프로젝트와 이동할 할 일을 확인한다. 프로젝트 이름 수정 및 항목 제외가 가능하다. 완료된 일은 일괄 재분류하지 않는다.
- Hermes 대화: 새 할 일의 승인 카드를 저장하기 전에 같은 분류 로직을 적용한다. 생성할 프로젝트도 카드에 포함하며, 승인 전에는 아무 데이터도 생성하지 않는다. 명시적으로 고른 프로젝트는 `autoAssign:false`로 유지한다.
- 그래프: 프로젝트 페이지는 그래프로 시작한다. 프로젝트를 선택하면 해당 프로젝트의 키워드와 소속 할 일을 보여준다. 키워드 선택 시 연결된 목록이 좁혀지고 할 일을 누르면 상세 편집이 열린다. 완료 포함, 기록 및 목표 표시도 지원한다.

새 프로젝트 후보는 로컬 규칙으로 추출한 제안이다. 임의의 사업 관계를 추론하거나 기존 프로젝트의 목표를 덮어쓰지 않는다. 새 프로젝트 목표는 비워 두고 목표일은 첫 할 일의 마감일로 시작한다. 같은 정규화 이름은 기존 프로젝트로 연결한다. 직접 생성·편집한 프로젝트의 키워드를 추가하면 이후 분류가 개선된다.

`task.upsert`는 선택적인 `project` 및 `autoAssign`, `task.assign`은 선택적인 `projects` 배열을 받는다. 기존 명령과 호환되며 스키마 마이그레이션은 없다. 할 일 ID와 진척, 첨부/원문 참조를 유지하고 연결된 내부 일정의 프로젝트도 함께 변경한다. 공유 회의록은 원래 프로젝트에 남는다. 잘못된 대상이 하나라도 있으면 전체 명령을 거절하며 동일 operationId 재요청은 한 번만 적용한다.

검증: `npm run typecheck`, `npm run test:brainy`, `npm run test:storage`, `npm run test:agent`, 빌드 후 `npm run test:smoke`. 실제 예시 여섯 건이 일일 프로젝트 하나에만 속한 상황, 중복 이름, 모호한 일치, 수동 선택, 원자적 저장, Hermes 승인, 프로젝트별 그래프 목록을 포함한다.
