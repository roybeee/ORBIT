# Orbit v0.3 · 개인 위키에서 다음 행동으로

## 이번에 사용할 수 있는 기능

| 기능 | 사용 방법 |
|---|---|
| 문서별 본문 저장 | 회의록·위키·지식을 작성하면 본문이 개별 문서 버전으로 저장됩니다. |
| 본문 검색 | 개인 위키·지식창고에서 제목·본문·태그로 검색합니다. 목록은 24개씩 표시합니다. |
| 변경 이력과 복원 | 문서를 열고 ‘이전 내용 확인 · 복원’을 누릅니다. 선택한 버전과 현재 내용을 확인한 뒤 복원하면 새 버전이 생깁니다. |
| 회의록에서 할 일 등록 | 회의록의 명시된 할 일 후보를 선택하고 제목·마감일·예상 시간·완료 기준을 확인해 등록합니다. |
| 원문 추적 | 등록한 할 일에서 승인한 원문, 문서 버전, 행 번호를 확인할 수 있습니다. |
| 전체 현재 기록 내보내기 | 설정에서 JSON 내보내기를 실행합니다. 별도 저장된 모든 현재 문서 본문도 포함됩니다. |

기존 기록은 그대로 읽을 수 있습니다. 다음 저장 시 기존 원문과 ID·할 일 연결을 함께 보존하며 새 저장 구조로 전환합니다. 저장 실패 시 전환도 함께 취소됩니다.

## 회의록 작성 예

아래는 사용법을 위한 가상 예시입니다.

```text
결정: 이번 주에는 제안서 초안까지 작성한다.
할 일: 제안서 초안 작성
- [ ] 협업사 검토 의견 요청
```

이 경우 명시한 할 일 두 개가 후보가 됩니다. 결정문 자체는 자동으로 할 일이 되지 않습니다. 아직 AI 해석은 연결하지 않았으며 `할 일:`, `액션:`, `TODO:`, `ACTION:`, `- [ ]` 표기만 읽습니다.

마감일과 시간은 사용자가 확인해 정합니다. 한 번에 최대 20개를 승인할 수 있습니다. 선택하지 않은 항목은 회의록에 남습니다. 등록한 항목은 같은 원문을 반복 승인하거나 회의록의 다른 부분을 수정해도 중복 등록하지 않습니다. 원문을 바꾸면 새 후보로 볼 수 있으므로 등록 전 확인합니다.

할 일 등록과 캘린더 배치는 별개입니다. 저녁 회고 뒤 제안을 생성하고 승인하면 집중 시간으로 반영됩니다.

## 기록의 보존 범위

- 수정할 때마다 제목·본문·프로젝트·태그를 문서 버전으로 보관합니다. 이력은 10개씩 불러옵니다.
- 복원은 과거 버전을 지우지 않고 새 버전으로 저장합니다. 과거 프로젝트가 삭제되어 연결할 수 없으면 복원을 거절합니다.
- 문서를 삭제하면 그 문서의 이력도 삭제됩니다. 연결된 할 일이 있으면 삭제할 수 없습니다.
- 내보내기는 현재 기록과 본문을 포함합니다. 과거 문서 이력, 작성 중인 입력, 가져오기/복구 기능은 포함하지 않습니다.
- 본문을 분리해 이전의 전체 본문 합계 한도는 없앴습니다. 문서당 100,000자와 요청 400,000바이트 제한, 목록·업무 데이터 합계 950,000바이트 제한은 남아 있습니다. 대량 자료 가져오기는 다음 저장 구조 확장 후 제공합니다.

## GitHub 연결 상태

**저장소 생성과 GitHub 업로드는 아직 완료하지 못했습니다.** `roybeee` 계정 연결은 확인했지만 접근 가능한 저장소/설치가 없고, 현재 연결 도구에는 저장소 생성 기능이 없습니다. 이 작업 환경의 GitHub CLI 인증도 없습니다.

[GitHub 생성·연결 안내](GitHub_Connect.ko.md)에 비공개 저장소 생성 링크와 인증된 환경에서 생성·업로드를 진행하는 스크립트를 준비했습니다. CI와 Issue/PR 양식은 코드에 포함되어 있습니다. 기존 소스 변경 이력은 Sites의 별도 Git 원격에 보관합니다.

## 확인한 범위

로컬 검증 35개: 일정 제안 8개, 저장·날짜 10개, 문서·이전 구조 전환·검색·승인 11개, 빌드한 서버 HTTP 경로 6개. 계정 간 격리, 원문 보존, 저장 실패의 전체 취소, 이전 버전 복원, 검색 페이지 경계, 중복 승인 방지, 본문 포함 내보내기를 확인합니다.

실제 휴대폰 설치와 브라우저 조작 검증은 아직 수행하지 않았습니다. AI 분석, Notion/Google Calendar 연동, 자동 저녁 실행·푸시 알림은 다음 개발 단계입니다.
