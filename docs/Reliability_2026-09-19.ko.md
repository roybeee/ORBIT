# 실행 신뢰성·복구 개선

운영 중인 Sites 소스(2026-09-17)를 기준으로 변경했다. GitHub의 9월 8일 소스만 기준으로 다시 배포하면 이후 추가된 서버 예약 실행, 전체 백업, 업무 실행 기능이 사라질 수 있어 운영본을 보존했다.

## 업무 판단과 네 결함

- `work-policy.ts`가 완료·보류일·선행 업무·막힌 사유·상위 목표·주간 사업 배분을 판단한다. 계획, 승인, 핵심 업무 지정, Laser, 시작, 페이스메이커와 운영 제안이 이 정책을 공유한다. 다른 집중 세션은 지금 시작할 때만 막으며 미래 계획을 막지 않는다.
- 운영본에 이미 있던 blocker 검사를 공통 정책으로 옮기고 여러 진입점을 함께 검증했다.
- Hermes 미연결 계획의 재시도는 처리 영수증을 버전 검사보다 먼저 확인한다. 날짜·에너지·명령 종류를 바꾼 재시도는 거절하며, 이후 Hermes를 연결해도 이미 끝난 로컬 계획을 다시 실행하지 않는다.
- 달력 수집은 요청 버전 검사 후 진행한다. 수집 자체가 바꾼 버전 때문에 정상적인 새 계획 요청이 충돌하지 않는다. 기존의 외부 일정 충돌 방지는 유지한다.
- 집중 구간과 빈 시간의 교집합에 실제로 배치하며 앞뒤 남은 시간을 보존한다. 이미 승인한 항목도 핵심 결과물 최대 개수에 포함한다.

## 앱 밖 조사 실행

기존 예약 실행기는 계속 사용한다. `runtime-work.ts`에서 저장된 실행을 한 단계씩 처리하고, 수집·보고서 준비와 번갈아 배정한다. 수집이 계속 밀려도 조사 실행을 진행한다. 승인 대기는 자동 승인하지 않으며 중지 요청은 처리 대상에 남긴다. 기존 실행별 잠금과 중복 제출 방지 키를 사용한다.

`lastSchedulerTick`은 인증된 예약 실행 요청만 갱신한다. 수동 상태 확인으로 예약 실행기의 중단이 가려지지 않는다. 예약 실행 설정 갱신은 내부 커서와 최근 실행 기록을 보존하며 참·거짓 값의 JSON 형식도 유지한다. Hermes 자체가 필요한 작업은 연결된 Hermes 실행 환경이 켜져 있어야 한다.

## 보관·복구

기존 전체 ZIP 백업, 문서 변경 이력, 원본 첨부, 대화·실행 기록, 선택 복구, 휴지통을 보존한다. 원본과 SHA-256 검증값, 계정별 분리, 재시도, 원자적 복구 테스트를 실행했다.

`storage-usage.ts`가 실제 저장 형태의 UTF-8 용량과 950,000바이트 한도를 정의한다. 외부 달력 캐시와 별도 보관하는 문서 본문은 제외한다. 백업 화면에 사용량과 80% 경고를 표시하며, 복원 미리보기에서 합친 결과가 한도를 넘으면 즉시 거절한다. 복원 후 예상 용량도 확인할 수 있다. 데이터 스키마 변경이나 운영 기록의 일괄 삭제는 없다.

## 모듈과 검증

설정 화면을 `workspace-settings.tsx`, 선택 입력을 `choice.tsx`로 분리했다. 업무 판단·서버 실행 진행·저장 용량 계산은 화면과 독립된 모듈이다. 빌드 시간 제한은 macOS와 Linux에서 같은 Node 실행기를 사용한다. CI는 전체 테스트를 실행한다.

- 타입 검사 통과.
- 전체 테스트 341개 통과(새 회귀 검사 14개 포함).
- 배포용 Worker 빌드 및 내장 검증 161개 통과.
- 실제 브라우저 조작 검사는 수행하지 않았다. 빌드된 Worker의 HTTP·인증·화면 응답은 자동 테스트로 검사했다.

운영 확인은 배포 완료 후 예약 실행기의 전용 기록 갱신을 확인한다. 되돌릴 때는 이전 Sites 버전을 배포할 수 있으며, 이번 변경에는 되돌려야 할 DB 마이그레이션이 없다.
