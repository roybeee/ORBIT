# ORBIT 디자인 시스템

버전 1.0 · 2026-09-19 · 제품 디자인 및 개발 전달 기준

이 문서는 ORBIT의 브랜드, 화면, 구성 요소, 인터랙션에 적용할 제작 규격이다. 문서에 등장하는 기능·상태는 디자인 요구사항이며 실제 서비스의 구현·연동·배포 완료를 뜻하지 않는다. 최종 전달 파일의 존재 여부는 별도 자산 목록으로 확인한다.

## 1. 브랜드 방향

**ORBIT — 나의 페이스메이커.**

목표에 닿을 때까지 나를 살피고, 먼저 움직이는 AI 비서실장. 사용자 한 사람을 중심으로 일정, 할 일, 프로젝트, 지식, 실행 결과가 연결된다.

| 항목 | 기준 |
|---|---|
| 핵심 인상 | 차분함, 명료함, 연결감, 전진 |
| 시각 언어 | 기울어진 궤도, 하나의 위성, 깊은 남색, 절제된 라벤더와 시안 |
| 제품 원칙 | 오늘 해야 할 일과 다음 행동이 화면에서 먼저 보인다. |
| 우주 표현 | 진입 화면·브랜드 영역에서 넓게 사용하고 작업 영역에서는 낮은 대비의 배경으로 제한한다. |
| 문장 | 짧은 한국어 동사형. “추가”, “수정”, “내일로 이동”, “제안 검토”. |
| 상태 표현 | 결과와 다음 행동을 함께 알린다. “저장하지 못했어요. 다시 시도해 주세요.” |

장식용 별, 궤도, 그라데이션은 정보의 위계보다 강하게 보이지 않아야 한다. 기능명에 우주 은유를 강요하지 않는다. 메뉴에는 ‘미션’, ‘우주선’ 대신 ‘프로젝트’, ‘일정’, ‘지식’처럼 바로 이해할 수 있는 표현을 사용한다.

## 2. 로고 규격

### 심벌 구성

기본 좌표계는 `viewBox="0 0 100 100"`이다.

| 요소 | 정확한 규격 |
|---|---|
| 중심 원 | 중심 `(50,50)`, 반지름 `28`, 채우기 없음, 선 두께 `10` |
| 궤도 | 중심 `(50,50)`, `rx=46`, `ry=13`, 회전 `-32°`, 채우기 없음, 선 두께 `2.5` |
| 위성 | 중심 `(86,23)`, 반지름 `5` |
| 선 끝·연결 | round cap, round join |
| 기본 색 | 중심 원 `currentColor`, 궤도 `#9C8CFF`, 위성 `#9C8CFF` |
| 1색 버전 | 모든 도형에 `currentColor`; 어두운 바탕은 흰색, 밝은 바탕은 남색 |
| 보호 여백 | 심벌 바깥 실제 경계에서 최소 `10` 좌표 단위 |

원 → 궤도 → 위성 순으로 그린다. 위성 뒤에 배경색 원을 추가해 궤도와 2단위 이상 분리할 수 있다. 투명 배경이나 임의 배경에 사용하는 범용 SVG에는 특정 배경색을 박아 넣지 않는다. 작은 크기는 같은 마스터의 가독성을 확인한다. 향후 별도 광학 보정본을 제작할 경우 자산 목록에서 구분한다.

### 배치와 변형

- 기본 조합: 심벌 + `ORBIT` 대문자 워드마크. 간격은 심벌 높이의 20%, 워드마크 대문자 높이는 심벌 높이의 42%.
- 가로 로고 최소 너비: 화면 112px. 심벌 단독 최소 크기: 24px. 현재 아이콘·파비콘은 동일한 100×100 마스터를 사용한다. 별도 16px 광학 보정본은 이번 자산에 포함되지 않는다.
- 아이콘: 1024×1024px 정사각형에 중심 배치. 현재 Maskable SVG는 마스터에 `translate(17,17) scale(.66)`를 적용한다. 플랫폼별 마스크를 미리 합성하지 않는다.
- Android 적응형 아이콘은 전경·배경 레이어를 분리하고 중앙 안전 영역 안에 모든 식별 요소를 배치한다. 실제 기기 마스크별 검수 필요.
- 워드마크의 자간은 글자 크기의 `0.06em`. 최종 로고 배포본은 글꼴 차이로 형태가 바뀌지 않도록 문자 윤곽선을 확정한다.
- 늘이기, 임의 회전, 위성 추가, 무작위 글로우, 사진 위 저대비 배치 금지.
- UI 안의 작은 로고는 평면 벡터를 사용한다. 입체 렌더와 빛 번짐은 홍보용 이미지에만 사용한다.

## 3. 테마와 의미 기반 색상

`bg`, `surface`, `text`, `textMuted`, `primary`, `onPrimary`, `borderSubtle`은 제작된 테마에 맞춘 값이다. 나머지는 구성 요소 적용을 위한 확장 제안이며 앱 반영 완료를 뜻하지 않는다.

코드에서는 색상값을 직접 반복하지 않고 의미 기반 토큰을 참조한다. 사용자 선택을 저장하며 `system`, `dark`, `light`, `focus`를 구분한다. `system`은 기기 설정의 밝기만 따른다. Focus는 별도로 선택하는 집중 테마이다.

| 토큰 | Galaxy Dark · 기본 | Orbit Light · 밝은 환경 | Focus · 집중 |
|---|---|---|---|
| `bg` | `#080B16` | `#F4F6FB` | `#0D1119` |
| `surface` | `#11182A` | `#FFFFFF` | `#151B25` |
| `surfaceRaised` | `#182139` | `#EFF1F8` | `#1A2332` |
| `text` | `#F4F6FF` | `#182139` | `#F4F6FF` |
| `textMuted` | `#AAB6D0` | `#56647E` | `#AAB6D0` |
| `primary` | `#9C8CFF` | `#6653CC` | `#C1B8F4` |
| `onPrimary` | `#080B16` | `#FFFFFF` | `#080B16` |
| `secondary` | `#72DDF5` | `#0C718A` | `#A5B6CA` |
| `borderSubtle` | `#2C3853` | `#D1D8E6` | `#384355` |
| `borderControl` | `#8290B2` | `#717C96` | `#8290B2` |
| `success` | `#7DE0BB` | `#176A4C` | `#93CBB5` |
| `warning` | `#F4CB7F` | `#815600` | `#D1BD93` |
| `danger` | `#FF9EA9` | `#B52A45` | `#E7ABB4` |

`borderSubtle`은 카드 사이의 장식적 구분에만 사용한다. 입력 필드·체크박스 등 식별에 필요한 윤곽은 `borderControl`을 사용한다. 상태 색은 반드시 라벨이나 아이콘과 함께 표시한다.

**테마별 배경 규칙:** Dark는 상단 브랜드 영역에 라벤더·시안의 낮은 불투명도 방사형 그라데이션을 허용한다. Light는 밝은 단색 표면과 얕은 그림자를 사용한다. Focus는 별 배경, 장식 그라데이션, 자동 재생 애니메이션을 제거한다. 모든 테마에서 화면 구조와 버튼 위치는 동일하다.

### 확인한 대비

불투명한 단색 조합의 상대휘도 계산값이다. 실제 화면에서는 반투명, 이미지, 호버, 비활성 등 합성 결과를 다시 확인한다.

| 전경 / 배경 | 대비 |
|---|---:|
| Dark 본문 `#F4F6FF` / `#080B16` | 18.20:1 |
| Dark 보조 글자 `#AAB6D0` / `#11182A` | 8.68:1 |
| Dark CTA 글자 `#080B16` / `#9C8CFF` | 7.11:1 |
| Light 본문 `#182139` / `#F4F6FB` | 14.76:1 |
| Light 보조 글자 `#56647E` / `#F4F6FB` | 5.52:1 |
| Light CTA 글자 `#FFFFFF` / `#6653CC` | 5.72:1 |

일반 글자는 4.5:1, 큰 글자 및 필수 비문자 그래픽은 3:1 이상을 목표로 검수한다. 비활성 표현은 투명도만 낮추기보다 전용 표면·문구를 사용해 읽을 수 있게 유지한다.

## 4. 타이포그래피

외부 웹폰트 다운로드를 전제로 하지 않는다.

```css
--font-ui: -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo",
  "Malgun Gothic", "Noto Sans KR", "Segoe UI", sans-serif;
```

| 역할 | 모바일 / 데스크톱 | 굵기 | 행간 |
|---|---|---:|---:|
| 브랜드 히어로 | 36 / 56px | 700 | 1.15 |
| 화면 제목 | 28 / 32px | 700 | 1.3 |
| 섹션 제목 | 20 / 22px | 700 | 1.4 |
| 카드 제목 | 16 / 16px | 600 | 1.45 |
| 본문 | 15 / 15px | 400 | 1.6 |
| 버튼·입력값 | 16 / 16px | 600 / 400 | 1.5 |
| 보조 정보 | 13 / 13px | 400 | 1.5 |
| 작은 라벨 | 12 / 12px | 600 | 1.5 |

한글 본문 자간은 `0`을 기본으로 하고 제목만 `-0.02em`까지 허용한다. 숫자 시각 정렬에는 `font-variant-numeric: tabular-nums`를 사용한다. 설명문은 읽기 폭을 60자 안팎으로 제한하고 입력 화면에서는 텍스트 확대를 막지 않는다.

## 5. 공간, 레이아웃, 형태

- 기본 간격: `4, 8, 12, 16, 24, 32, 48, 64px`. 모바일 좌우 여백 20px, 밀도가 높은 일정 화면만 16px 허용.
- 모서리: 컨트롤 12px, 카드 20px, 큰 패널 24px, 바텀시트 상단 28px, 태그 999px.
- 모바일 화면은 단일 열. 768px 이상 보조 패널을 허용하고, 1200px 이상 좌측 탐색 + 본문 + 선택적 문맥 패널을 사용한다.
- 본문 최대 폭 1280px. 전체 폭 표와 캘린더는 기능에 맞춰 예외를 둔다.
- 모바일 하단 탭: 오늘 / 일정 / 프로젝트 / 지식 / 전체. 현재 탭은 아이콘과 라벨, 배경 변화로 함께 표시한다.
- 전체 메뉴에서는 연결, 설정, 기록 등 보조 기능에 접근한다. 주요 화면에는 설치 안내나 서버 설정을 상시 노출하지 않는다.
- 하단 탭과 고정 작성 버튼은 기기 safe-area를 고려한다. 가상 키보드가 열렸을 때 입력과 완료 동작을 가리지 않는다.
- 모든 표면에 그림자를 넣지 않는다. Dark는 윤곽·명도 차이, Light는 얕은 그림자를 우선한다.

## 6. 핵심 화면 규칙

| 화면 | 처음 보이는 정보 | 주요 행동 |
|---|---|---|
| 오늘 | 날짜, 오늘의 핵심 목표, 다음 일정, 우선 할 일 | 빠른 추가, 완료, AI 제안 검토 |
| 일정 | 선택 날짜, 시간축, 일정명과 시간 | 일정 추가, 이동, 수정 |
| 프로젝트 | 진행 중인 프로젝트, 다음 행동, 기한 | 프로젝트 열기, 다음 할 일 추가 |
| 프로젝트 상세 | 목표, 다음 행동, 작업 목록, 관련 기록 | 작업 진행, 자료 연결 |
| 지식 | 검색, 최근 저장, 프로젝트 연결 | 기록 작성, 자료 찾기 |
| AI 비서 | 요청 입력, 진행 상태, 결과, 승인할 제안 | 지시, 검토, 승인 또는 보류 |
| 전체 | 기능 목록, 연결 상태, 환경 설정 | 원하는 메뉴 찾기 |

오늘 화면의 카드 수는 최초 화면에 3~4개를 목표로 한다. AI 제안은 사용자가 승인하기 전 확정 일정과 구분한다. 진행률이 실제 업무 데이터에서 계산되지 않았다면 임의의 백분율을 표시하지 않는다.

## 7. 구성 요소와 상태

| 요소 | 시각·동작 기준 | 반드시 정의할 상태 |
|---|---|---|
| 기본 버튼 | 화면당 주 행동 1개, 높이 48px, 단색 primary | 기본, hover, 눌림, focus, 처리 중, 비활성 |
| 보조 버튼 | 표면 + 윤곽, 높이 48px | 기본, hover, 눌림, focus, 비활성 |
| 파괴적 동작 | danger 글자·아이콘, 대상명을 확인 | 기본, 확인, 처리 중, 실패 |
| 아이콘 버튼 | 아이콘 20~24px, 터치 영역 48px | focus, 선택, 비활성; 접근 가능한 이름 |
| 입력 | 명시적 라벨, 도움말, 오류 메시지 | 빈 값, 입력, focus, 오류, 읽기 전용, 비활성 |
| 작업 행 | 완료 컨트롤 + 제목 + 최소 메타정보 | 예정, 진행, 완료, 기한 경과, 저장 중, 실패 |
| 일정 카드 | 시간·제목·출처를 읽을 수 있게 표시 | 확정, 제안, 충돌, 동기화 중, 실패 |
| 프로젝트 카드 | 이름, 다음 행동, 기한, 근거 있는 진행 정보 | 진행, 보류, 완료, 비어 있음 |
| 상태 배지 | 작은 점 또는 아이콘 + 상태 텍스트 | 정상, 진행, 주의, 실패 |
| 토스트 | 한 문장 결과, 필요한 경우 되돌리기 | 성공, 실패, 되돌림 가능 |
| 바텀시트 | 제목·닫기·핵심 입력·고정 완료 영역 | 열린 상태, 처리 중, 검증 오류 |
| 검색 | 검색어, 지우기, 결과 수, 필터 | 기본, 검색 중, 결과, 결과 없음, 실패 |
| AI 결과 카드 | 요청과 결과, 실행 상태, 출처·시각 | 접수, 작업 중, 검토 필요, 완료, 실패 |

로딩은 실제 진행 상태가 없는 경우 백분율 대신 스피너 또는 스켈레톤으로 표시한다. 네트워크 실패 화면에는 마지막 표시 데이터의 시각과 재시도를 제공한다. 빈 상태에는 ‘아직 없어요’와 최초 행동을 함께 배치한다.

## 8. 제스처, 키보드, 접근성

- 일정 순서·시간 변경: 길게 누르기 400ms 후 드래그 시작. 이동 전 원래 자리 표시, 이동 중 예상 시간 표시, 저장 실패 시 원위치 복구와 설명. 길게 누르는 동안 일반 스크롤을 불필요하게 막지 않는다.
- 왼쪽 스와이프: 수정·삭제 동작 노출. 제스처를 모르는 사용자도 항목의 더보기 메뉴에서 동일 기능에 접근할 수 있어야 한다.
- 프로젝트 길게 누르기: 수정·보관·삭제 메뉴. 삭제 실행은 항목명과 영향을 표시한 확인 단계에서 처리하며, 복구 가능한 데이터 모델일 때만 ‘되돌리기’를 제공한다.
- 드래그 기능에는 키보드로 이동할 수 있는 ‘위로 / 아래로 / 시간 변경’ 대안을 제공한다. 이동 결과를 스크린리더에 알린다.
- 터치 대상 최소 44×44px, 기본 48×48px. 인접 위험 동작 사이 간격 8px 이상.
- 키보드 포커스는 2px 외곽선과 3px offset으로 항상 보이게 한다. 팝업 열기 전 포커스를 기억하고 닫을 때 원래 대상으로 반환한다.
- 모달 내부 포커스 관리, Escape 닫기, 접근 가능한 제목, 입력 오류와 필드 연결이 필요하다.
- 확대 200%, 320px 화면 폭, 시스템 글자 크기 확대에서 핵심 정보·행동이 사라지지 않는지 확인한다.
- 색상만으로 기한 경과·선택·오류를 구분하지 않는다. 정보 전달에 필요 없는 별과 궤도는 보조기술에서 숨긴다.

## 9. 모션

| 동작 | 시간 | 규칙 |
|---|---:|---|
| 버튼 눌림 | 120ms | 표면 또는 명도 변화; 이동량 최소화 |
| 탭·선택 변화 | 160ms | 색상·밑줄·표면 전환 |
| 카드·패널 등장 | 220ms | 8px 이내 이동과 opacity |
| 바텀시트 | 280ms | easing `cubic-bezier(.2,.8,.2,1)` |
| 완료 표시 | 240ms | 체크 표시 1회; 반복 없음 |
| 브랜드 궤도 | 선택적 | 진입·홍보 영역에서만; 업무 영역의 상시 회전 금지 |

`prefers-reduced-motion: reduce`에서는 장식 이동과 반복 재생을 끄고 상태 전환을 즉시 또는 80ms 이하 opacity 변화로 표시한다. Focus 테마에서는 별도의 사용자 설정과 무관하게 장식 모션을 끈다. 업무 알림은 반짝임으로 표현하지 않는다.

## 10. 제작 자산 목록

아래는 전체 디자인 패키지가 갖춰야 할 명세이다. 실제 파일 목록과 혼동하지 않도록 전달 시 `manifest`에서 생성 완료 여부를 기록한다.

| 자산 | 형식·크기 | 사용 |
|---|---|---|
| 마스터 심벌 | SVG, 100 좌표계 | 제품·벡터 원본 |
| 로고 가로 조합 | SVG, dark/light/mono | 헤더·소개 화면 |
| 앱 아이콘 | PNG, 1024·512·192px | 원본·PWA용 |
| 플랫폼 아이콘 | Android 전경/배경, iOS 원본 | 앱 배포용 별도 검수 |
| 파비콘 | SVG 및 16·32·48px | 브라우저 |
| 테마 토큰 | JSON + CSS custom properties | 제품 개발 |
| 배경 아트 | WebP 또는 AVIF + 원본 | 온보딩·배경; 텍스트 없는 이미지 |
| 브랜드 보드 | PNG | 브랜드 확인 |
| UI 화면 세트 | PNG 또는 편집 가능한 디자인 | 모바일·데스크톱 주요 화면 |
| 인터랙티브 미리보기 | HTML/CSS/JS 또는 앱 소스 | 테마·컴포넌트 상태 확인 |
| 디자인 규격 | Markdown | 개발 전달 |

파일명 예: `orbit-symbol.svg`, `orbit-logo-dark.svg`, `orbit-icon-1024.png`, `orbit-tokens.css`, `orbit-background-galaxy.webp`. 래스터 콘셉트 이미지에 포함된 글자는 최종 로고·UI 자산의 원본으로 사용하지 않는다.

## 11. 개발 전달과 완료 기준

1. 토큰·구성 요소·화면 순으로 적용한다. 테마값은 `data-theme` 또는 동등한 루트 속성에서 전환한다.
2. 모든 화면은 같은 버튼, 카드, 입력, 배지, 바텀시트 구성 요소를 사용한다. 한 화면만 별도 색상·모서리를 도입하지 않는다.
3. 자산 `manifest`에 파일명, 용도, 규격, 생성 상태, 실제 경로를 기록한다. 시안과 배포 자산을 구분한다.
4. 데모 데이터에는 명확한 ‘미리보기’ 표시를 둔다. Google Calendar·HERMES·ASIDE 연결 상태와 성과 수치를 임의로 실제처럼 표시하지 않는다.
5. 주요 화면을 390×844px, 768px, 1440px에서 확인한다. 세 테마·빈 상태·로딩·오류·긴 제목·글자 확대를 포함한다.
6. 앱에 실제 반영하려면 현재 저장소의 UI 구조, 인증·연동 상태, 플랫폼별 아이콘 설정을 확인한 뒤 적용한다. 디자인 패키지 완성과 앱 배포 완료는 별도로 보고한다.

핵심 전달 원칙은 **하나의 심벌, 같은 화면 구조, 세 가지 읽기 환경, 명확한 다음 행동**이다.
