# ORBIT × ASIDE 연결 프로그램

ASIDE의 로그인된 브라우저에서 조회·조사·초안 작성을 실행하고 ORBIT에 결과를 회수합니다. ASIDE의 선택된 기본 모델과 기존 플랜을 사용합니다. 별도의 모델 API 키는 필요하지 않습니다. 플랜의 사용량·모델 제한은 ASIDE 정책을 따릅니다.

## 처음 한 번

1. ASIDE 앱을 열고 유료 가입 계정으로 로그인합니다. Settings → Developers에서 공식 CLI를 설치합니다.
2. Node.js 22 이상이 없다면 https://nodejs.org/ 에서 LTS를 설치합니다.
3. 압축을 모두 풀고 `START-WINDOWS.cmd`를 실행합니다. 계정 목록에서 사용할 **account ID**를 입력합니다. 계정을 바꾸려면 `SETUP-ACCOUNT.cmd`를 실행합니다.
4. 자동으로 열린 ORBIT에 로그인하고 **ASIDE 실행 → 이 PC 연결 테스트**를 누릅니다. 브라우저가 로컬 네트워크 접근을 물으면 이 ORBIT 사이트에 허용합니다. ChatGPT 안의 미리보기 대신 독립된 브라우저 탭을 사용합니다.
5. 연결된 계정을 확인하고 **이 PC에서 대기 업무 실행**을 켭니다. 업무 카드를 선택하고 정확한 사이트·기간·범위를 작성한 다음 대기열에 추가합니다.

Windows CLI가 사용자 지정 경로에 있다면 `ASIDE_EXECUTABLE` 환경 변수에 실제 `.exe` 또는 `.js`의 절대 경로를 지정할 수 있습니다. 명령 셸을 통한 임의 실행은 지원하지 않습니다. 공식 ASIDE CLI가 설치된 macOS에서는 터미널에서 `node bridge.mjs`를 실행합니다. Linux용 ASIDE CLI는 확인되지 않았습니다.

## 매일 사용하는 흐름

- ORBIT: 오늘 할 조사와 정리 업무를 지시하고 프로젝트에 연결합니다.
- ASIDE: 로그인된 웹사이트를 조회하고 근거 URL을 포함한 결과를 만듭니다.
- ORBIT: **결과 검토 → 위키에 저장 → Hermes에 검토 요청**으로 기억과 다음 행동을 연결합니다. Hermes 버튼은 검토 요청을 대화 입력창에 넣으며 전송은 직접 합니다.
- 매출 대조, 문의 답변 초안, 영수증 목록, 경쟁사 변화, 회의 후속 조사 프리셋을 편집해 반복 사용합니다. 발송·결제·삭제·제출은 실행 유형과 정확한 대상·내용·금액을 등록하고, ORBIT에서 해당 요청을 승인한 뒤 대기열에 들어갑니다. ASIDE의 실제 권한·추가 승인 절차는 그대로 유지됩니다.

## 동작 범위와 복구

- 새 업무 전달과 결과 회수에는 PC·연결 프로그램·ORBIT 탭이 켜져 있어야 합니다. PC 연결 방식은 PC 전원이 필요합니다. PC 없이 실행하려면 아래 서버 자동화를 사용하세요. 탭을 닫아도 이미 시작된 로컬 실행은 이어질 수 있으며, 동일 PC에서 다시 연결하면 보관된 결과를 회수합니다.
- 잠자기·강제 종료·네트워크 장애가 생기면 같은 업무를 다른 PC에서 자동 재실행하지 않습니다. ASIDE에서 실제 작업 상태를 확인하고 ORBIT의 **ASIDE 종료 확인**으로 복구합니다.
- 중지 버튼은 로컬 CLI 프로세스에 중지를 요청합니다. ASIDE의 브라우저 작업까지 중단됐다고 보장할 수 없으므로 ASIDE 화면에서 직접 확인해야 합니다.
- CLI 종료 코드 0은 업무 성공 확인이 아닙니다. ORBIT에서 결과와 출처를 검토한 뒤 **검토 완료**를 누릅니다.
- ASIDE의 기존 권한·승인 설정을 유지합니다. 업무 프롬프트는 운영 지침이며 기술적인 읽기 전용 권한을 강제하지 않습니다. 로그인·인증·추가 승인 요청은 ASIDE 화면에서 처리하세요.

## PC 없이 예약 실행·ODA 반영

ORBIT **서버 자동화**는 상시 실행되는 ODA 서버와 기존 Hermes 연결을 사용합니다.

1. ODA **정산 관리 → 자동화 연결**에서 매장·매출/비용·반복 실행 범위의 연결 키를 발급해 ORBIT에 등록합니다.
2. 서버에서 접근할 수 있는 사이트와 대상, 요일·시각·시간대를 입력하고 예약을 저장합니다. ASIDE PC의 로그인 세션은 서버로 이동하지 않습니다.
3. 결과 처리에서 **매출·비용 수집 → ODA 반영 검토**를 고르면 수집 결과가 ODA 검토 목록에 기록됩니다. 원본·금액을 검토하고 승인하면 실제 매출·비용에 반영됩니다.
4. **실행·승인 기록**에서 결과와 Hermes의 추가 승인 요청을 확인합니다. 서버 재시작 후 실행 기록을 복구하며, 불명확한 실행은 실제 종료를 확인할 때까지 같은 업무의 중복 실행을 막습니다.

예약은 PC나 ORBIT 탭이 닫혀 있어도 실행됩니다. ODA 서버·Hermes 서버가 실행 중이고 연결이 유효해야 합니다. Hermes 원격 승인은 서버가 제공하는 승인 요청을 전달하며 모든 도구에 대한 별도 권한 엔진은 아닙니다. 외부 발송·결제·제출 도구의 기존 승인 정책을 유지하세요.

ODA 원천 거래 ID와 금액을 비교해 중복·충돌을 검사하고 확정·지급된 정산월은 변경하지 않습니다. 수집 결과만으로 증빙 검토 완료나 세무 확정을 표시하지 않습니다.

## 개인 정보와 연결

연결 키는 PC의 실행 중인 프로그램과 ORBIT 탭의 세션 저장소에만 존재합니다. ORBIT 서버에는 전달하지 않습니다. 로컬 서버는 `127.0.0.1:43127`에만 바인딩하고 지정된 ORBIT 출처와 인증 키를 검사합니다. 연결 주소·키를 공유하지 마세요.

전체 로그와 실행 기록은 사용자 홈의 `.orbit-aside`에 보관됩니다. 로그에는 브라우저 문맥이 포함될 수 있습니다. ORBIT에는 제한된 활동 설명과 최종 텍스트만 전달합니다. 위키 저장과 Hermes 검토는 버튼을 눌러 진행합니다. 로그를 삭제하면 해당 PC의 복구·중복 방지 기록도 사라지므로 모든 작업을 종료한 후 처리하세요.

## 문제 해결

- 연결 실패: 프로그램 창이 열려 있는지, ORBIT를 같은 PC의 독립 탭에서 열었는지, 사이트의 로컬 네트워크 권한을 허용했는지 확인합니다.
- CLI 호환성 미확인: ASIDE를 업데이트하고 공식 CLI를 다시 설치합니다. `aside exec --help`에서 `--account`와 `--log-dump`를 확인할 수 있어야 합니다.
- 계정 오류: `SETUP-ACCOUNT.cmd`로 다시 설정합니다. 이미 배정된 작업은 처음 선택한 계정에서만 복구됩니다.
- 다른 프로그램이 포트를 사용 중이면 시작하지 않습니다. 기존 ORBIT 연결 프로그램을 확인하세요.
